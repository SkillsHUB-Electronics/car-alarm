# Firmware (`car_alarm/`)

Main sketch: `car_alarm/car_alarm.ino`. It also compiles for the ESP32 DevKit (`esp32:esp32:esp32`, BLE UART on Serial2; compile-checked in CI, **not tested on hardware**). Open the `car_alarm` folder in the Arduino IDE, install the **LiquidCrystal I2C** library (Frank de Brabander), select the Arduino Uno board and upload. Or compile/upload from the web console's local helper (`console/server`).

> Firmware 2.1 (13/10/2026): adds `HW`, `I2C,SCAN`, `IO,BL`, `IO,BT` and ax/ay/az in `DBG`; Flash 70%, SRAM 60%; tested on a UNO over USB. The EEPROM layout changed, so settings revert to defaults once.
>
> Status: **compiles** (arduino-cli, Arduino UNO). Phase 6 (12/10/2026): without a model Flash 66%, SRAM 59% (828 B free); with the 8→12→14 model Flash 76%, same SRAM. The firmware 2.1 commands were tested on a UNO over USB; calibration, learning and the model have not been exercised against real road data.

## Modules
| File | Role |
|---|---|
| `config.h` | All pins, I2C addresses, thresholds and timings. Change values only here |
| `types.h` | State/level/event enums |
| `DistanceSensor` | HC-SR04 at 10 Hz, median of 3, hysteresis, 1 s hold before dropping a level (`DIST_RELEASE_HOLD_MS`; rises immediately), a timeout never triggers an alarm |
| `Motion` | MPU6050 (direct registers): calibration at start, shock and hard-braking detection |
| `Alerts` | LED and buzzer pattern per state |
| `Display` | 16x2 LCD, redraws only when the text changes |
| `BtLink` | Outgoing messages to **USB and BLE at once** (protocol in `app/README.md`), including `FEAT` and `CLS` |
| `Commands` | Line commands from USB and BLE (table below); replies go to the originating channel |
| `Settings` | Thresholds and distance calibration in EEPROM (defaults from `config.h`) |
| `Classifier` + `model_data.h` | Small edge-AI MLP in PROGMEM; `model_data.h` is generated by the web console (the stub means no model) |

## Behaviour
- Safe >100 cm (green LED), warning 50-100 cm (yellow slow blink, one beep per second), danger ≤50 cm (red fast blink, fast beeps). Leaving a level requires passing the threshold +5 cm.
- Shock/hard braking: red LED on, continuous buzzer for 3 s, state shown for 10 s then clears itself (no button).
- Priority: shock/brake > danger > warning > safe.
- Distance is sent to the phone every 0.5 s and when the level changes; shock/brake are sent immediately (3 s cooldown per type).
- If the MPU6050 is missing, the LCD shows `ERR` and the distance alarm keeps working.

## Commands (USB 9600 and BLE, PLAN.md D12)
Send one line ending in a newline. Replies `RSP,...` or `ERR,...` go to the originating channel; events go to both.

| Command | Reply / effect |
|---|---|
| `HW,GET` / `HW,RESET` | `RSP,HW,<LCD address decimal>,<lcd>,<backlight>,<charger>,<ina>` |
| `HW,SET,<address 8-119>,<lcd 0/1>,<backlight 0/1>,<charger 0/1>,<ina 0/1>` | stores in EEPROM and applies to the LCD immediately. Charger/INA **have no function yet**, they are only stored |
| `I2C,SCAN` | `RSP,I2C,<count>,<decimal address>...` (max 8) |
| `IO,BL,<0/1>` / `IO,BT,<text>` | (during `IO,ON`) temporary backlight; text sent to the phone over BLE |
| `PING` or `VER` | `RSP,VER,<version>,<model 0/1>` |
| `CFG,GET` / `CFG,RESET` | `RSP,CFG,warn,danger,shock×100,brake×100,brakeMs,holdS,buzzer` |
| `CFG,SET,<7 values>` | stores in EEPROM if valid (danger+10 ≤ warning, ranges in `Settings.cpp`) |
| `CAL,GET` / `CAL,RESET` | `RSP,CAL,<gain>,<offset>` |
| `CAL,RAW[,n]` | `RSP,CAL,RAW,<mean raw distance ×10 cm>` (blocks ±0.6 s) |
| `CAL,SET,<gain>,<offset>` | correction `true = raw×gain + offset` (gain 0.5-2; offset ±50) |
| `IO,ON` / `IO,OFF` | manual test mode; exits by itself after 30 s without commands |
| `IO,LED,<R/Y/G>,<0/1>`, `IO,BUZ,<0/1>`, `IO,LCD,<line1>|<line2>` | set outputs (only during `IO,ON`) |
| `IO,READ` | `RSP,IO,READ,<raw distance ×10>,<ax>,<ay>,<az mg>,<mpu>,<lcd>` |
| `REC,START,<0-31>` / `REC,STOP` | send `FEAT,<label>,f0..f7` every second (milli-g) |
| `DBG,<0/1>` | line `DBG,status,cm,shockDev,fwd,pkShock,pkBrake,pkAccel,ax,ay,az` every 0.5 s (ax/ay/az in mg, sensor frame); used by the dashboard for the IMU |

Outgoing events: `OK/WARN/ALARM,DIST,<cm>`, `ALARM,SHOCK|BRAKE,<g>`, `FEAT,...` (only while recording), `CLS,<class>,<percent>` (only if a model is present). Note: `SoftwareSerial` drops incoming bytes while it is transmitting; the app/web page retries when there is no reply and shows the reply values for verification.

Learning features: 8 features per 1-second window (vertical/lateral/forward std, forward mean, |lateral mean|, vertical peak, forward min/max) in the car frame (forward = `FORWARD_AXIS`, vertical = the other axis that carries gravity most).

## MPU6050 calibration (D7), to be done later
1. Send `DBG,1` from the web console or a 9600 baud Serial Monitor (format `DBG,status,cm,shockDev,fwd,pkShock,pkBrake,pkAccel`). Power on while the car is **stationary and level** (1 s calibration at start).
2. Column `shockDev` (column 3) = |magnitude - 1 g|; `fwd` = forward acceleration (+) / braking (-).
3. Forward direction: push or slowly accelerate/brake the car. If braking gives a positive `fwd`, set `FORWARD_SIGN` to `-1`. If the forward axis is not X, change `FORWARD_AXIS` (0=X, 1=Y, 2=Z).
4. Record `shockDev` on ordinary driving, speed bumps and slammed doors; choose `SHOCK_G` above the normal values. Do the same for ordinary vs hard braking for `BRAKE_G`.
5. Send `DBG,0` when done.

## Notes
- The HC-SR04 read blocks for up to 25 ms when there is no echo; MPU sampling can slow down briefly, which is fine for the current detection.
- Pins D0/D1 are not used so uploads do not conflict with Bluetooth.
